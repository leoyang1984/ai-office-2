# 研发决策

| 日期 | 决策 | 理由 |
| --- | --- | --- |
| 2026-11-10 | P0 使用显式版本的 npm CLI 与 TS SDK，均为 0.2.2-rc.1 | 发行标签默认值不一致；所选版本的源码和包可逐项对照 |
| 2026-11-10 | 只使用 `sdk` profile，使用干净的 HOME、DSH Home、cwd 和子进程环境 | 不访问个人 DSH 数据；`sdk-minimal` 在主机上的默认权限不符合规格 |
| 2026-11-10 | 将 SDK 往返、云模型应答和容器隔离分别验收 | 分开标记真实运行时、真实模型和底层权限，避免由任何单项推断其余项目通过 |
| 2026-11-10 | 先在当前目录交付探针和证据，阶段闸门满足后建立独立项目 | 当前目录位于上层硬盘元仓库下；用户要求验证后开始项目实现 |
| 2026-11-10 | 用已安装的 Docker Desktop 完成 ARM64 权限探针 | 宿主实测通过了只读挂载及跨用户访问拒绝，P2 继续验证实际 DSH Worker |
| 2026-11-10 | 云探针继承当前 shell 的 HTTP(S) 代理环境变量并使用 `deepseek-flash` | 干净环境的直连探测超时，使用代理能收到官方服务响应。模型名以 [DeepSeek 官方 API 文档](https://api-docs.deepseek.com/) 为准 |
| 2026-11-10 | P1 使用 Fastify、Zod、better-sqlite3 和 React。服务在同一 origin 上提供 API 和静态页面 | 共享校验和 OpenAPI 契约简化前后端接入。Cookie、Origin 和 Host 一起限制浏览器会话 |
| 2026-11-10 | 知识库登记限托管目录的一级子目录，下载按所有者与文件 ID 查询 | 固定允许访问的根目录。下载检查链接、文件身份、大小和哈希 |
| 2026-11-10 | P1 只启用 Mock Agent | P2 用实际 Worker 复测运行时权限和撤权 |
| 2026-11-10 | P2 Worker 使用 `--network=none`。模型流经受限 stdio 消息送到宿主上的 DeepSeek 代理 | 容器可用自己的本地 HTTP 端口和 SDK。代理只访问固定 DeepSeek 地址、限模型和响应大小，云 Key 留在宿主 |
| 2026-11-10 | P2 每轮用独立容器，成功后保存 DSH session id 并按需恢复 | 进程生命周期与租户授权绑定。撤权时先等待旧 Worker 停止，再更新授权 |
| 2026-11-10 | P3 图片经文件所有权校验后以 SDK 原生图像块发送 | 浏览器和真实 DSH Worker 的合成验收核对 PNG 字节完整性 |
| 2026-11-10 | 每轮创建独立成果目录，Worker 结束后安全登记 | 限制扫描数量及大小，避免跟随软链接或把特殊文件当成果 |
| 2026-11-10 | P4 使用停机快照和独立恢复目录 | SQLite 在线备份 API 生成一致的数据库文件，数据锁保证工作区复制期间无服务写入 |
| 2026-11-10 | P4 先用本机临时 TLS 代理验收 HTTPS | 本机可验证浏览器链路。第二台设备的真实 Tailnet 测试保留为独立闸门 |
| 2026-11-11 | 手机真实云模型验收与本机合成自动化证据分别记录 | 用户实测确认远程图片处理和文件下载；不将手工验收冒记为 `cloud` 自动测试执行 |
| 2026-11-11 | A20 故障注入限随机临时数据作用域和容器 tmpfs | 验证崩溃、超时、清理及恢复，同时保留用户当前服务与数据 |
| 2026-11-11 | 产品方向调整为官方 DSH Web 复用，按用户隔离实例 | 用户明确要保留原版对话体验，统一增加账户与权限；改造计划 R0–R5 单独验收，不复用旧版 PASS 结论 |
| 2026-11-11 | 公共镜像与公共 Skill 共用，个人数据和 Skill 分别持久化 | 控制重复程序存储，同时保留用户权限边界；具体 Web 与 Skill 加载兼容性在 R0/R3 实测 |
| 2026-11-11 | R0 复用既有镜像内的官方 Web 包，保持 network=none，以 stdio 多路通道承载 Web 和受限模型流量 | 原版页面、RPC、WebSocket 和恢复已实测，避免为 Web UI 放开容器外网 |
| 2026-11-11 | R0 探针与 R1 账户网关分开，原生文件读取与用户下载按钮分别验收 | 测试 Cookie 隔离不能替代平台鉴权，原生字节下载可行不等于页面已有下载按钮 |
| 2026-11-11 | 每次最终总结提供下一次提示词 | 按用户最新要求，便于按阶段继续工作 |
| 2026-11-11 | R1 原生 Cookie 和启动令牌只在服务端交换，R1 传输不发布 TCP 入口 | 所有原版 HTTP/WS 都必须经过平台会话校验，不能以 DSH 凭据绕过平台身份 |
| 2026-11-11 | 退出/改密/禁用直接撤销已登记连接，另周期检查到期；HTTP 读取 body 前登记 | 即时切断 WebSocket 和未完成上传，避免只限制后续登录 |
| 2026-11-11 | 用官方 UI 槽提供下载与账户操作，按用户隔离浏览器缓存 | 保留原版对话界面；同源换账号也必须清除上一身份的持久化草稿 |
| 2026-11-11 | R1 原版 CSP 限定到原版路径，配置写入只放行固定欢迎标记 | 兼容官方动态模块，同时保留平台登录页原有策略和配置 API 最小清单；插件/profile 锁定仍属 R2 |

| 2026-11-11 | R2 在 prompt 接受前占用轮次名额，由原生 wait 确认静止后释放 | 覆盖整轮工具与模型循环，HTTP/WS 绕行不获名额；后台请求不能自动重启空闲实例 |
| 2026-11-11 | 原版 profile、插件、工具预设固定在只读镜像，状态目录独立持久化 | 旧配置和工作区 .env 不参与启动，保留原版聊天界面与历史 |
| 2026-11-11 | 采用五项工具清单、规范化文件范围、静态 HTML 和双层存储限制 | 容器挂载强制只读知识库，应用层检查总量和 OS 限单文件；R3 引入 Skill 时继续受同一执行边界约束 |

| 2026-11-11 | R3 公共授权按不可变版本挂载，个人保存经平台更新 | 同一公共版本共用一份来源，个人独立，名称冲突先于实例停止拒绝 |
| 2026-11-11 | R3 使用固定发现根与声明式文本包 | Skill 加载继续受 R2 执行边界约束，安装不运行包内代码或系统依赖 |

| 2026-11-11 | R4 从私有快照迁移到新根，使用原版 RPC 登记已验证的会话 | 保留 ID 和原容器工作目录，保留旧 SQLite 文字作为可读归档 |
| 2026-11-11 | 快照格式 2 纳入 R3 文件与数据库，恢复兼容格式 1 | 原版与旧 SDK 的维护共享锁，回滚以迁移前快照为基准 |

| 2026-11-11 | R5 使用独立的本机端口、测试 Cookie、前台 Serve 和临时数据根 | 同一 Tailnet 主机名上的不同端口可共享 Cookie，专用名称避免测试登录覆盖正式会话 |
| 2026-11-11 | 单独为原版附件模块配置租户状态根，并有界排队并行上传 | 保留只读配置与逐件存储配额，同时支持原版多选上传 |
