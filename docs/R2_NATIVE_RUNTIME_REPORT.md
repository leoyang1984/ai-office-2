# R2 原版 DSH 实例与权限验收

日期：2026-11-11。R2 使用独立临时数据、合成账户/知识库和合成模型响应。原版 DSH 0.2.2-rc.1、Docker ARM64、Chrome、实际文件工具参与验收。原 SDK/Mock 启动方式、正式入口、Tailnet 和真实数据未改动。

## 实例、轮次和权限

- 登录和首次改密不启动容器。打开原版页面或提交明确的工作请求时，为服务端识别出的账户启动独立实例；最多同时两个。SQLite 独占锁保护同一数据目录，启动时只清理 R2 标签与数据目录范围均匹配的孤儿容器，不干预其他项目和测试。
- 默认无工作请求 5 分钟后回收；正在运行的 turn 和正在写入的请求不被空闲计时回收。单纯的 WebSocket 连接和被动重连不会唤醒实例。原页面提示「继续使用 DSH」，点击后重建实例，重新打开原生历史。回收不删除文件。
- 提交 `session/prompt` 前按账户占用名额，收到接受回执后由网关查询原版 `session/wait`，确认不再运行且队列为空才释放。每账户一个 turn、默认全局两个、每 turn 最长 120 秒。拒绝转向、队列修改、WS 执行等其他入口。取消只能针对当前轮次所在会话；超时、异常或撤权会停止执行并清理。浏览器断开时，已经接受的 turn 仍受同一超时和配额约束。
- 模型代理只接受已获准的 turn；每 turn 最多 12 个模型请求、同一实例同时一个模型请求。保留固定模型、输出上限和宿主代理，拒绝超出工具清单的模型请求。测试全程无需真实 Key，模型 Key 不传入容器。
- 管理员修改知识库授权时，先切断受影响用户的 HTTP/WS 并停止实例、取消模型请求，再提交授权变更。重建时只加载当前授权。已被用户读入历史或下载的内容无法通过撤权收回。

## 平台配置和存储

- 平台 profile、官方组件、浏览器模块及额外的下载控件在只读镜像层；启动从只读目录执行，不加载工作区或旧 DSH Home 里的 profile、插件或 `.env`。原版 CLI 启动会重写空 Loader 根文件，预加载模块仅在字节与预置文件完全一致时跳过第一次写入；其余写入由正常文件系统执行。Web 内部登录凭据单独保存在容器临时目录。
- 仅开放 `read`、`read_image`、`write`、`edit`、`present`，禁用 shell、终端、插件管理、其他执行预设、子 Agent、任务调度和工作流执行。原版搜索通过未受文件服务约束的子进程运行，默认的 working_directory 工具可改变目录；R2 停用这两个入口，模型出口复核五项工具清单。配置 API 无写入例外；固定欢迎标记及关闭开发视图由镜像提供。
- 实际文件工具在解析规范路径后，只读本人工作区和已挂载的授权库，只写本人工作区。知识库在 Docker 层只读，未授权库和他人目录不挂载。容器非 root、只读根文件系统、无外网和宿主端口，限制 CPU、内存、进程数及临时目录大小。HTML 走原版静态预览，用户文档的脚本、事件处理器无法执行。
- 工作区和持久化 DSH Home 合计默认 100 MiB、500 个目录条目。启动和写入前检查，用上传体积预留空间；实例运行时每 500 ms 检查，超限后停止实例并拒绝重启，保留文件供管理员处理。单文件有 32 MiB OS 写入上限，容器临时目录为 64 MiB tmpfs。总量是应用层上限：两次检查间可能暂时超出，不是卷级硬配额。不以真实磁盘写满做验收。

## 实测与修复

| 复跑项 | 实测内容 |
| --- | --- |
| `node tests/security/r2-runtime.ts` | 数据目录独占、按范围清理孤儿、启动按需；A08–A12、A21 的实容器挂载、实际工具、文件哈希和撤权检查；每账户与全局并发、取消、空闲恢复、超时、崩溃、字节和条目配额 |
| `node tests/e2e/r2-browser.ts` | 原版静态 HTML 预览不执行脚本或事件处理器；真实浏览器保持打开仍会回收；点击恢复、打开旧记录并继续 |
| `node tests/security/r1-host.ts` / `node tests/e2e/r1-native.ts` | R2 镜像上复跑 R1 主机鉴权、慢上传中断、双账户官方界面、下载、缓存清理、密码重置和禁用 |
| `pnpm test`、严格类型检查、R0 双实例与 SDK 历史 | 验证旧 SDK 路线及探针回归；R0 合成历史兼容测试仍用其锁定镜像 |

自动探针将全局轮次上限设为 1，让两个真实实例争用名额，并缩短空闲与超时、降低存储阈值以验证边界。另测试正常页面文件生成、下载及历史续聊。

启动验收先发现 CLI 重写配置根和原版登录必须创建临时凭据；修复后关闭依赖已停用服务的终端界面模块。安全探针又发现官方补丁拒绝在原组件 ID 上直接更换模块，改为停用旧组件并显式插入受限文件组件，且构建遇到未应用补丁即失败。原版默认开启开发视图，固定关闭后复测真实 HTML。对话取消与撤权使用两个独立会话，以便区分两次模型中止。

R2 镜像标签 `ai-office-2-dsh-web:r2-0.2.2-rc.1`，复用固定的 R1 镜像。验收镜像 ID：`sha256:c8d9ef204cdd92690fe1bd25862b9156674aff1f29261cac06014bd332c40927`。应用仍仅通过 `createApp({ nativeWeb: ... })` 接入该运行时；常用启动命令没有自动切换。

## 复跑

在项目根目录、Docker Desktop 运行且固定 R1 镜像存在时：

```sh
export PATH="$PWD/.runtime/node-v24.21.0-darwin-arm64/bin:$PATH"
export TMPDIR=/private/tmp
sh scripts/build-web-r2.sh
pnpm typecheck
pnpm test
node tests/security/r2-runtime.ts
node tests/e2e/r2-browser.ts
node tests/security/r1-host.ts
node tests/e2e/r1-native.ts
node tests/e2e/r0-web.ts
node tests/security/r0-sdk-web.ts
```

公共与个人 Skill 留给 R3；真实数据迁移及切换回滚留给 R4；手机上的真实云模型 HTTPS、原版完整上传类型和边界矩阵留给 R5。
