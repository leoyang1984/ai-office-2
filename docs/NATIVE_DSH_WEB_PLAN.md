# 官方 DSH Web 复用改造计划

日期：2026-11-11。状态为 R0–R4 已通过测试验收，见 [R0 报告](R0_NATIVE_WEB_REPORT.md)、[R1 报告](R1_NATIVE_GATEWAY_REPORT.md)、[R2 报告](R2_NATIVE_RUNTIME_REPORT.md)、[R3 报告](R3_SKILLS_REPORT.md)和 [R4 报告](R4_MIGRATION_REPORT.md)。R5 手机 HTTPS、两种账户登录和真实云模型回复已确认，手机文件、Skill、断线恢复和撤权待实测，见 [R5 验收手册](R5_TAILNET_REPORT.md)。现有 SDK 版本保留，运行入口未切换。

## 目标与规格优先级

保留官方 DSH 对话界面，AI Office 负责统一登录、账户管理、按用户隔离、知识库与 Skill 授权及运维。每位用户进入项目管理的独立 DSH Web 实例；所有实例复用同一份固定版本镜像，各自持有独立持久化数据。用户无需在自己的设备安装 DSH。

本计划及 SPEC.md 顶部的改造说明优先于原 SPEC 中有关自建会话页、仅 SDK 执行、每轮创建 Worker 的规定。原规格的账户安全、底层隔离、只读授权、隐私保护、测试闸门和不干扰现有应用的要求继续有效。既有 P0–P4 的 PASS 属于 SDK 工作台，不自动适用于新 Web 运行时。

## 目标结构

- 浏览器：统一登录及管理入口，进入官方 DSH Web 对话页面。
- AI Office 网关：根据服务端登录身份选择该用户实例；统一检查 HTTP 和 WebSocket，管理连接、授权、配额、审计及实例生命周期。
- 用户实例：官方 DSH Web，独立 HOME、DSH Home、工作区和持久化会话；知识库及公共 Skill 按授权只读挂载。
- 公共内容：固定版本 DSH 镜像和管理员维护的公共 Skill 版本。多个容器共用镜像层，用户数据与缓存分别增长。
- 模型访问：优先复用宿主受限代理，平台 Key 留在宿主；新 Web 模型出口和配置权限需单独验证。

只在 ai-office-2 内开发。个人 DSH Desktop/Web、AI Office 1.0、真实知识库、现有服务和真实用户数据不作为试验对象。初期沿用已锁定的 DSH 0.2.2-rc.1；升级属于单独变更。

## 分阶段实施

### R0 — 原版界面与双实例可行性探针（已通过）

交付：项目专用 Web 镜像、最小测试转发器、自动浏览器探针及原版 Web 兼容性报告。

1. 核对锁定版本发布包包含的官方 Web 静态资源、启动参数、配置覆盖、模型接口与运行依赖，保留许可声明。检查已有镜像能否扩展；缺依赖则构建一个公共 Web 镜像，不在每个用户启动时联网安装。
2. 在全新临时数据目录准备 A、B 两个合成租户；通过同一镜像分别启动独立 DSH Web 容器。使用临时 loopback 端口与测试转发入口，不替换当前 3000 服务或 Tailnet 配置。
3. 验证静态资源、HTTP RPC、WebSocket、上传、图片及下载通过完整官方链路运行；先用合成模型，无需真实 Key。
4. 验证独立会话列表、事件、目录及重启后的历史恢复；访问其他实例及未授权文件应失败，已授权只读库的写入应在 OS 层失败并保持哈希一致。
5. 先评估保留无外网容器、通过受控隧道转发 Web 流量的实现。若需要调整容器网络，先记录威胁分析与替代限制，并验证跨容器、宿主、局域网和互联网直连均不能绕过网关；不能直接沿用旧网络测试的 PASS。
6. 用同版 SDK 合成会话数据验证官方 Web 的发现、显示和继续能力，明确迁移缺口；不读取实际使用中的会话。

闸门：两个实例的官方页面与聊天、文件、重启恢复正常，关键隔离负向测试通过，网络与模型凭据方案有实测依据。若不通过，修复并报告，不接入真实账户；不自行退回自建聊天界面。

### R1 — 统一账户网关（已通过测试验收）

交付：复用现有登录、改密、账户管理，增加身份到实例的服务端绑定与官方 Web 接入。

- 目标实例只能由服务端当前身份确定，不能由浏览器提交的用户 ID、端口、URL 或 Cookie 任意选择。
- 所有 HTTP 请求及 WebSocket 握手都检查 AI Office 会话。DSH 自己的凭据仅用于访问相应实例，不能代替平台登录或绕过账户状态。
- 处理路径前缀、Host/Origin、HTTPS、Cookie、缓存和静态资源；验证登出再换账号不显示前一用户数据。
- R0 已确认原版二进制读取可用于浏览器下载，但缺少通用下载按钮。R1 通过官方界面扩展槽或独立小扩展补充，保留原版对话 UI。
- 退出、重置密码、禁用用户后，关闭受影响的现有连接并拒绝新请求；不能只禁止下一次登录。
- 模型配置、插件、终端及目录选择按明确权限清单控制，后端同样执行限制。优先通过官方配置与项目扩展实现，必要的源码改动应单独记录。

闸门：A/B 经统一入口使用原版界面；跨账户 HTTP、WebSocket、文件与事件访问失败，失效登录会话不能继续操作。

### R2 — 实例调度与完整权限边界（已通过测试验收）

交付：生产用 Web 实例管理器，复用并适配现有容器加固、用户目录和知识库授权。

- 每用户独立实例按需启动，空闲时可回收；持久化目录保留。初期最多两个活跃用户实例，超额请求明确等待或拒绝，不为全部账号永久常驻进程。
- 同一用户可有多段历史对话，初期限制同时一个模型 turn；原版 Web 的其他调用入口同样不能绕过限制。
- 锁定平台控制的 profile、客户端插件和执行配置，验证 Agent 无法通过写本人配置绕过平台策略；补测恶意脚本与预览在共享浏览器中的边界。
- 授权变更先终止相关执行和连接，再更新挂载并重建实例。新实例不再拥有撤销的知识库或 Skill。
- 重新验证非 root、只读程序层、资源与时间限额、Docker socket/宿主 Home/SSH agent 不可用、固定模型出口与 Key 不进入用户容器。
- 补齐异常退出、超时、取消、孤儿容器清理、重启恢复和存储配额测试。审计记录运行状态，避免记录密钥及完整私密内容。

闸门：原 SPEC 安全硬闸门 A08–A12、A21 在新 Web 路线上重测通过；原版 HTTP/WS 不能绕过并发和授权限制。

### R3 — 公共与个人 Skill（已通过测试验收）

交付：管理员维护公共 Skill、按用户授权加载，个人 Skill 独立持久化。

- 公共 Skill 安装一次、版本固定、按授权只读提供。授权以实际文件和运行可见性为准，不能只过滤界面列表。
- 个人 Skill 放在本人持久化目录，不写入公共镜像或共享库。安装包中含脚本时遵守同样的容器、网络及文件权限。
- 验证官方发现路径、刷新与重启行为、撤权、同名 Skill 冲突。初期拒绝未经明确处理的同名覆盖，防止个人 Skill 静默替换公共规则。
- 系统包和运行依赖由管理员统一打包进镜像；Skill 说明可共享，不代表任意 Skill 的全部依赖已经可用。需要写入自身目录的 Skill 必须先适配或标记不兼容。
- 使用新建合成 Skill 验收，不读取或迁移本机个人 Skill、凭据或知识库。

闸门：共用 Skill 实际只存一份，用户运行产物各自隔离；无授权的 Skill 不可读，公共内容不可改，容器重建后个人 Skill 仍存在。

### R4 — 历史兼容与切换准备（已通过测试验收）

交付：迁移工具或明确兼容方案、备份恢复与可回滚的切换步骤。

- 根据 R0 的兼容实测建立会话、用户目录和文件的映射；区分 SDK 工作台的展示记录与 DSH 原生持久化记录，不承诺直接替换网页即可继承。
- 先用合成数据完整演练备份、迁移、恢复和回滚，测试旧记录可读、新会话可继续，明确尚不能迁移的内容。
- 实际切换前停机创建私有快照，以独立数据副本验证新版本，保留旧版代码、镜像与原目录。不得让两个运行时同时写同一份 DSH Home。
- 在原版 Web 对话体验验收通过后，再切换当前入口；不在探针阶段替换生产服务或修改全局网络设置。

闸门：恢复和回滚实际演练成功；迁移结果及任何缺口可复核，原数据保持可用。

### R5 — 手机远程及最终验收

交付：真实 Tailnet 手机验收、新版自动化矩阵、启动停止/备份更新文档与运行报告。

- 本机自动化覆盖新版完整链路：登录与改密、原版 UI、文本/图片、上传下载、工具状态、WebSocket 重连、会话恢复和幂等。
- A/B 普通账户完成正向与越权测试。旧 SSE 测试不能代替新版 WebSocket 的身份、事件归属及断线恢复测试。
- 复测并发、超时、进程崩溃、资源限额、撤权、禁用和异常清理；每项注明合成模型或真实模型、自动或手工、未测试范围。
- 手机经真实 HTTPS 完成原版界面对话、文件和重新登录恢复历史。需要云模型凭据时，仍由用户在本机终端隐藏输入，不读取现有应用的 Key。
- 更新 README、兼容性、风险、实施记录和部署文档。常驻与开机启动另行配置，不因本次改造自动修改系统服务。

闸门：功能与安全测试均通过才宣布新版完成。

## 复用范围与执行纪律

复用账户库、密码安全、目录和知识库管理、容器加固基础、备份基础及 Tailnet 入口。调整或替代自建聊天界面、SDK 消息执行路径、每轮容器生命周期和相应数据展示映射。旧版在切换前继续保留。

每阶段先测试，记录失败和修复，更新 IMPLEMENTATION_LOG、DECISIONS、RISKS 后再推进。每次面向用户的最终总结附上下一次可直接复制的提示词。代码和文档在 main 上维护，提交前审查暂存内容和隐私钩子；不推送任何真实数据或密钥。

R0 已以临时合成数据完成官方 Web 双实例、隔离、文件、重建恢复及 SDK 会话兼容探针，未切换真实服务入口或迁移用户数据。R1 已完成平台鉴权、连接撤销、原版下载按钮和缓存分离测试；R2 已验收按需启动、空闲回收、轮次并发、授权撤销、只读平台配置和故障配额。R3 已验收公共版本一次安装、按授权只读挂载、个人 Skill 独立保存、刷新和撤权。R4 已用合成数据通过旧 SDK 会话导入、原版续聊、新版恢复和旧版回滚。R5 真机验收闸门仍开放。
